# The Alexa+ add-on package

`addon.json` is the manifest CIRCA would be submitted with, written to the
`addon.json` schema reference published in the
[Alexa+ MCP QuickStart Guide](https://developer.amazon.com/docs/alexaplus/add-ons/mcp-toolkit-quickstart.html):
the store listing nested under `storeListing.locales["en-US"]`, `privacyAndCompliance`
carrying both policy URLs, `mediaAssets` carrying the icon set and a carousel
image, and an `MCP` integration whose default endpoint declares
`"type": "HTTPS"`.

It is checked rather than eyeballed. `tests/addon.test.ts` asserts the nesting
(and that nothing from the store listing has drifted back to the top level), the
name at 30 characters, the short description at 123, the full description at
4,000, three to four example phrases each at 200, alt text at 250, both policy
URLs HTTPS, all six required icon sizes with files that exist at those
dimensions, at least one 600x900 carousel image, and the endpoint type.

**An earlier version of this file claimed the test "asserts every documented
constraint", and it did — against a flat manifest of its own invention.** Every
assertion passed on a document the CLI would have rejected at the first key it
read. The lengths were right and the shape was not, which is the failure mode a
test written from the same misunderstanding as the code will always have.

## The media

`media/` holds the six icons and the carousel image, generated by script from the
product's own palette and from a real screenshot of the comparison card. The URIs
in the manifest point at `raw.githubusercontent.com`, so they resolve once the
repository is public, which it is.

The icon is a ring left open, with the unanswered question sitting in the gap.
That is the product.

## The endpoint

**`https://circa.example.com/mcp`, and that host does not exist.** `example.com`
is reserved by IANA for exactly this, and it is written that way so that nobody —
a judge, or a future me — mistakes it for a deployment. There is no public CIRCA
endpoint. `docs/AWS.md` records what was and was not run against AWS.

To point the manifest at a real server, replace that one URI and turn on the
account-linking gate:

```bash
CIRCA_AUTH=1 CIRCA_PUBLIC_URL=https://your-host pnpm mcp
```

The OAuth 2.1 profile Alexa+ drives — authorization code with PKCE S256, RFC 9728
protected-resource metadata, RFC 8414 authorization-server metadata, RFC 8707
resource binding — is implemented in `apps/mcp-server/src/oauth.ts` and driven
end to end by `tests/oauth.test.ts`, including the five rejection paths and the
two-linked-accounts isolation case. See `docs/AUTH.md`.

## The toolkit

`alexa-ai new mcp` would have scaffolded this directory. It was not used, because
the quickstart's "Step 1. Download and install CLI" contains no download link,
no package name and no install command, and the obvious guess installs an
unrelated third-party package from npm. That is written up in
`docs/PRODUCT_FEEDBACK.md`, which is where it is useful to Amazon.
